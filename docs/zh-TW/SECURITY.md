# 安全問題回報

[English](../../SECURITY.md) | **繁體中文** | [日本語](../ja/SECURITY.md)

> 若各語言版本有歧異，以英文版為準。

## 請不要開公開 issue

請使用 GitHub 的私密漏洞回報，並依問題所在選擇 repo：

| 問題出在 | 回報到 |
|---|---|
| 本轉接頭：它如何處理 agent token、端點 URL 或它轉送的訊息 | [custodexa-mcp 私密回報](https://github.com/custodexa/custodexa-mcp/security/advisories/new) |
| Custodexa 服務端：授權、申請核准、工具呼叫帳本、遮罩、錄影，或 `POST /api/v1/mcp` 背後的其他任何部分 | [custodexa 私密回報](https://github.com/custodexa/custodexa/security/advisories/new) |

不確定屬於哪一邊時，請回報到本 repo。

透過這個管道送出的回報只有維護者看得到，公告發布之前不會公開任何內容。

## 回報時請盡量附上

以下都不是必要項目，缺項也不會被拒收：

1. 轉接頭版本（`initialize` 回傳的 `serverInfo.version`，或 release 標籤），以及它所連線的 Custodexa 版本
2. 你的 MCP 宿主與作業系統
3. 重現步驟
4. 影響：攻擊者能取得什麼，以及事先需要哪些存取權限
5. 你希望的署名方式，或希望不具名

切勿附上真實的 token、憑證、個人資料或客戶資料。若重現必須依賴特定資料，請描述它的形態，不要貼上原文。

## 測試時請遵守

- 只測試你自己擁有、或已取得書面授權測試的部署。本專案沒有公開測試環境。
- 不破壞資料、不存取不屬於你的資料，也不做阻斷服務壓力測試。

## 回報後的處理方式

本專案不提供回應時限（SLA）承諾，改以下列順序處理回報：

| 級別 | 處置 |
|---|---|
| Critical | 中斷當下的工作，優先於功能開發 |
| High | 排在下一批工作之前 |
| Medium／Low | 與其他安全項目一起列入 backlog |

已遭實際利用、或已有公開 PoC 的問題，提升一級處置。分級不會因為難以修補而下調。決定不修也是正當的結論，而且一定會附上理由。

## 公開揭露

修補釋出前請不要公開細節。若自你回報起 90 日內仍未有修補釋出，你可以自行公開，不需要徵詢同意。這是你的權利，不代表屆時一定會有修補。

修補會以 GitHub Security Advisory 公告，內容包含影響範圍、受影響版本、緩解方式，以及回報者署名（除非你希望不具名）。

## 支援的版本

安全修補只釋出於最新的 release。

## 本專案沒有的東西

- 漏洞獎金（bug bounty）。
- 正式的法律保護聲明（safe harbor）。維護者不會對遵守上述規則的善意回報者採取不利行動，但這是表明立場，不構成法律承諾。
