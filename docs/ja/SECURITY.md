# セキュリティ問題の報告

[English](../../SECURITY.md) | [繁體中文](../zh-TW/SECURITY.md) | **日本語**

> 各言語版の記述が食い違う場合は、常に英語版が正となります。

## 公開 issue は立てないでください

GitHub の非公開脆弱性報告をご利用ください。報告先のリポジトリは、問題がどこにあるかで選んでください。

| 問題の所在 | 報告先 |
|---|---|
| このリレー: エージェントトークン、エンドポイント URL、転送するメッセージの扱い | [custodexa-mcp への非公開報告](https://github.com/custodexa/custodexa-mcp/security/advisories/new) |
| Custodexa サーバー: 認可、申請の承認、ツール呼び出し台帳、マスク、録画、そのほか `POST /api/v1/mcp` の背後にあるすべて | [custodexa への非公開報告](https://github.com/custodexa/custodexa/security/advisories/new) |

どちらに該当するか分からない場合は、このリポジトリをお使いください。

この窓口から送られた報告はメンテナだけが閲覧でき、アドバイザリが公開されるまで何も公になりません。

## 書けるなら書いてほしいこと

以下はいずれも必須ではありません。項目が欠けていることを理由に報告が却下されることはありません。

1. リレーのバージョン（`initialize` で返る `serverInfo.version`、またはリリースタグ）と、通信先の Custodexa のバージョン
2. お使いの MCP ホストとオペレーティングシステム
3. 再現手順
4. 影響。攻撃者が何を得るのか、そのために事前にどのようなアクセスが必要なのか
5. クレジットの希望（匿名を希望する場合はその旨）

実在のトークン、資格情報、個人データ、顧客データは決して含めないでください。再現に特定のデータが必要な場合は、データそのものは貼らずに、その形式を説明してください。

## テストの前提ルール

- テストの対象は、ご自身が所有しているデプロイ、または書面で許可を得たデプロイに限ります。公開のテスト用インスタンスはありません。
- データの破壊、ご自身のものではないデータへのアクセス、サービス妨害を目的とした負荷試験は行わないでください。

## 報告後に期待できること

本プロジェクトは応答時間（SLA）を約束しません。代わりに、報告には次の順序で対応します。

| 深刻度 | 対応 |
|---|---|
| Critical | 進行中の作業を中断し、機能開発より優先します |
| High | 次の作業のまとまりより前に組み込みます |
| Medium / Low | バックログへ入り、他のセキュリティ項目とあわせて扱います |

すでに実環境で悪用されているもの、または PoC が公開されているものは、1 段階引き上げます。修正が難しいことを理由に深刻度を下げることはありません。修正しないという判断も正当な結論のひとつであり、その場合は必ず理由を添えます。

## 公表について

修正がリリースされるまでは詳細を伏せてください。報告から 90 日が経っても修正がリリースされない場合は、許可を求めずにご自身で公表してかまいません。これはあなたの権利であり、その時点までに修正が存在するという約束ではありません。

修正は GitHub Security Advisory として公表し、影響、影響を受けるバージョン、緩和策、そして報告者へのクレジット（匿名を希望される場合を除く）を記載します。

## サポート対象のバージョン

セキュリティ修正は最新のリリースにのみ提供されます。

## 本プロジェクトにないもの

- バグバウンティ。
- 正式な法的セーフハーバー。上記のルールに従う善意の報告者に対してメンテナが措置を取ることはありませんが、それは意思の表明であって、法的な約束ではありません。
